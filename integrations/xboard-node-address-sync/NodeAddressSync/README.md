# 2.1.0 转发面板连接授权（开发版，未部署）

新增允许接入的转发面板、独立配对 Token 和明确节点映射。Relay 来源独立接收，不依赖下述 DDNS 常驻任务；旧绑定不会自动迁移。完整配对、验证与上线限制参见交付包 README-CONNECTION-V2.md。

# 节点 IP 自动同步 2.0.0

新模式由面板常驻任务查询 DDNS；无需给换出的新机器安装本插件的代理。仍由原系统更换 IP、配置转发、启动节点并更新 DDNS。插件不参与这些操作。

## 如何判断新 IP

1. 管理员把入口实际更新的 DDNS 域名，与对应的面板节点明确绑定。A 和 AAAA 分开选择，记录必须是 DNS only。
2. 每 5 秒启动一轮查询。递归 DNS 仅用于发现权威服务器，最终 A/AAAA/CNAME 直接向权威服务器查询，禁用递归；不缓存最终地址。
3. 最多询问三个不同权威服务器；配置多个时至少两个同意，已收到的不同答案会拒绝本轮更新。单一权威配置允许单源。跟随 CNAME，限制深度并拒绝循环、已知 CDN CNAME 和 Cloudflare 代理网段。
4. 默认只接受唯一公网 IP。多 IP 可明确选择固定数值最小者；不会轮询随机选址，也不会因某端口失败自动换成另一个候选。
5. 连续两轮、间隔至少 4 秒得到相同候选才进入检查。解析错误中断确认；超过 30 秒没有连续证据重新确认。
6. 对每个需要改址的节点检查新 IP 的**客户端连接端口**：AnyTLS/Trojan/Naive 等进行 TLS 握手，沿用原 SNI 和证书验证设置；HY2/TUIC 发送 UDP QUIC 版本协商包，要求正确匹配随机连接 ID 的响应。普通 TCP 节点进行 TCP 连接检查。
7. 网络检查在数据库事务外完成。提交时重新核对绑定版本、启用状态、当前节点配置及新鲜检查结果，防止检查期间的手工改动被覆盖。
8. 只更新检查通过的节点 `host`；保留端口、SNI、协议、倍率、用户组、ID 和可见状态。失败节点保留旧地址，下轮重试，其他节点可独立更新。

这里的检查证明从面板到新地址的传输层连接或 TLS 握手可用，不等同于用户认证成功、代理出网成功或所有地区都能访问。QUIC 版本协商也不验证 UDP 协议证书。加密混淆 UDP、REALITY、端口范围等暂不支持的检查类型一律保留原地址；不会用 TCP 成功代替 UDP 成功。插件不会替管理员修改证书或关闭验证。

## 配置

后台：节点管理 → IP 自动同步。选择“DDNS 权威解析”，填写源域名、A/AAAA、多地址规则，确认源记录后勾选节点。每个节点只属于一个绑定；最多启用 16 组、128 个节点。

普通编辑保留现有 `expected_host` 保护基线。手工修改过地址的节点保持受保护。确认这些节点确实仍属于本入口后，才勾选“接受所选节点当前地址为新的保护基线”。已删除节点清理映射；未启用节点跳过；隐藏但启用的节点按其显式绑定同步。

域名改为 IP 时，TLS 节点必须已经有正确 SNI。IPv6 保存为规范的不带方括号形式，订阅格式器负责 URI 方括号。客户端更新订阅才能取得新地址，插件不主动改写客户端缓存。

解析、检查、手工保护状态和失败节点 ID 显示在页面；页面每 10 秒刷新，关闭页面不影响后台任务。编辑期间固定使用开始编辑时的版本号，遇到其他管理员修改返回 409。

## 安装与运行

运行环境：现有 Xboard PHP/Laravel，PHP CLI 的 pcntl、posix、proc_open，Linux，Python 3.10+ 和系统 CA 证书。已随包附带 dnspython 2.8.0 wheel、校验和及许可证，不需要在生产环境 pip/composer 升级依赖。

先备份现有插件目录、该插件数据库记录及节点映射；仅执行本插件目录的迁移。迁移增加 DNS 字段和事件表，保留现有旧上报绑定与暂停状态。宿主的插件升级接口可能在完成时自动启用插件，维护脚本必须明确保留原启用状态。不要把旧绑定的当前节点集合未经核对直接改为一个 DDNS 来源。

把 `NodeAddressSync/` 安装至实际面板插件目录。常驻任务运行在能访问同一面板代码、数据库和 storage 的环境内：

```bash
cd /www
php plugins/NodeAddressSync/bin/worker.php
```

可用 `NODE_SYNC_APP_ROOT` 指定面板目录，`NODE_SYNC_PYTHON` 指定 Python。`--once` 只执行一轮，仍遵守两轮确认和启用检查。默认每 5 秒评估，超时采用有界预算，不重叠执行、不追赶积压。

Docker + systemd 示例在 `deploy/node-address-sync-ddns.service`，安装前核对容器名及路径。只启动此新增任务，无需重启节点、转发服务或容器。原面板为 Octane 时，新增界面/路由按现有方式平滑重载面板工作进程。不要重建或替换整个面板镜像。

任务锁和 PID 身份位于持久化 `storage/app/node-address-sync`，防止并发运行。停止命令验证 PID 的启动身份和命令行；禁止按通用 PHP/Python 名称杀进程。新任务停用或插件/绑定暂停后不再写节点，当前地址保留。

## 失败处理与时效

NXDOMAIN、空记录、无权威响应、权威结果冲突、非公网地址、CDN 代理、超时、缺少 SNI、检查失败、配置被改动：均保留节点原地址，不会清空地址。

健康情况下目标是从权威 DDNS 记录可见到面板保存及新订阅可读取小于 60 秒；上游 DDNS 尚未发布、服务未启动、连通失败、暂停或人工保护的时间不计为成功同步。当前隔离实测约 10.2–10.4 秒；这不是生产换机 SLA。

事件和地址历史保留 90 天。只记录固定错误代码、IP、节点 ID 和时间，不记录用户密码、代理认证配置、上报密钥或订阅令牌。

## 回滚

停止本插件新增常驻任务，保留当前节点地址。恢复备份的插件目录及原插件版本/启用状态；新增字段和事件表可以保留，兼容旧上报代码。不要回滚整个生产数据库、迁移所有插件或覆盖其他任务的安全修复。

如果需要撤回某次 DNS 写入，根据本插件历史逐节点检查：只有当前地址仍等于那次写入值、且没有后续人工更改时，才恢复对应旧地址。回滚程序不得盲目覆盖全表。

## 旧模式

旧实例上报接口、密钥哈希和安装脚本保留原有行为；新连通门槛针对 DNS 模式。旧模式资料见 `LEGACY_AGENT.md`。把绑定切到 DNS 模式后，旧代理上报返回 409，防止两个来源竞争。
