# NodeAddressSync 2.1.0 开发交付

这是联合开发与隔离验证产物，尚未部署。上传插件可能执行迁移并启用插件，不要将上传当作预览。

机场后台先创建“允许上报的转发面板”：填写 Relay 显示的固定面板 ID 和对应网址，明确勾选允许上报。新连接默认暂停。网址仅作识别，不用于回调或认证。

创建后复制机场地址和一次性配对 Token，在 Relay 后台填写并保存。Token 的复制格式为 `ns2.<connection_uuid>.<64hex_secret>`；Relay 自动拆出连接 ID，网络请求仍使用独立 64 位十六进制 Bearer 密钥。机场只保存密钥的 SHA256，不保存明文。

机场后台再选择该连接、填写对应 Relay 节点 ID，勾选允许修改的机场节点，保存为 Relay 来源绑定。Relay 点测试连接，从机场返回的授权映射里选择绑定。每个连接最多 100 个转发节点；不会按节点名或地区推断映射。隐藏节点仍可配置映射，是否可写由连接及绑定开关决定。

同一绑定只能使用 agent、DNS 或 Relay 一种来源。已有绑定不会被自动迁移、启用或改变凭据。Relay 来源拒绝旧实例直接上报，DNS 来源也不接受 Relay 更新。任一绑定节点被手工改址或删除时，整批停止写入；需要管理员核对后明确接受当前保护基线。

同步只通过原生 Server 模型保存 host，保留端口、协议、SNI、倍率、权限组及机器关联。机场端同步处理并返回带双方身份、转发节点、绑定、IP 的回执，不排入业务队列。

连接暂停或密钥轮换立即阻止旧凭据继续写入。轮换后需在 Relay 更新 Token 并重新测试连接。有映射的连接不能直接删除，可先暂停；解除绑定和删除连接保留现有节点地址。

使用 Relay 上报时，无须运行 DDNS 常驻任务。此开发包以既有未上线的 2.0.0 草案为基础，保留其 DNS 功能及旧实例兼容功能；两者的启用和部署仍需按各自流程单独处理。

## 验证与限制

当前运行 PHP 8.2.35、Laravel 12.70.1 下，以全新进程和独立 Application 验证真实路由、校验器、管理员中间件与原生模型。数据库为 SQLite `:memory:`，缓存为 array，认证为隔离假账号；未加载生产应用、未写真实业务数据或创建真实连接。临时文件在结束后移除。

验证涵盖独立密钥/面板身份/节点映射隔离、禁用与轮换、严格 JSON 类型、非法地址和时钟、重复及乱序回调、整批手工改址保护、字段保留、旧 schema 升级以及 v1 和 DNS 回归。浏览器检查为独立预览和假 API，覆盖 1440/390 像素、默认关闭、配对 Token、映射、秘密清除、XSS 转义及返回导航。

机场端毫秒级的隔离写入耗时不代表真实公网端到端延迟。正常单实例网络条件下以 30 秒为目标、60 秒为验收上限；真实换机、跨端连接、源端确认和实际部署仍待验收。双实例持续竞争、断网或身份错误必须显示冲突/失败，不能承诺在硬故障下强制完成同步。

## 部署与回退边界

本轮只交付源码、ZIP、逐文件哈希和验证记录，没有上传、迁移、连接/Token 变更、旧 reporter 停止或服务重启。未来上线需先备份实际运行插件、持久文件和受影响的配置行，验证自然回执，并单独协调旧 reporter 与新桥接的唯一写入者交接。

回退仅还原本次插件文件及本次新增配置。存在 Relay 绑定时，新迁移的 down 会拒绝删除授权表，避免回退把 Relay 绑定静默变成 v1 可写绑定。先暂停或解除本轮新映射，保留节点当前地址和审计记录；不要整库回滚。
