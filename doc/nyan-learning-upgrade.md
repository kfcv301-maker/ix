# Nyanpass 学习后的源码升级

本改动借鉴选择字段批量修改、节点诊断和恢复状态管理等设计，直接修改 Lunaris Relay 自有源码。提供的 Nyanpass 包包含编译后的 Go 程序和前端发布文件，没有完整 Go/React 工程；本改动没有运行破解脚本，也没有复制授权绕过、外部回传或 root Web 终端的实现。

## 已实现

### 选择字段批量修改

转发列表可选择当前可见规则，批量修改目标地址、出口网卡、负载均衡策略中的指定字段。执行前显示每条规则的前后差异；执行时重新取最新规则，跳过已暂停、异常、同步中、权限变化或预览后已修改的规则。保持规则所属用户、隧道、入口端口和 VPS 绑定。

按规则顺序提交并展示成功、失败、跳过。可单独重试失败项；如果第一次请求已生效但响应丢失，重试检查目标配置已满足后跳过，避免再次重建成功规则。

现有更新接口会重建选中规则的服务，可能中断其现有连接；批次没有整体回滚。列表检查和更新之间不是原子比较交换，并发窗口中其他页面的编辑或暂停仍可能竞争，因此界面提示执行期间避免同时操作这些规则。该功能不会自动运行任何批量修改。

### 复用连接隔离和生命周期

MTCP、MTLS、MWS、MWSS 在首次握手前重复拨号时复用待握手连接，避免将尚未建立 smux 的会话误认为已关闭。TLS/WebSocket 升级保留底层连接身份，并发握手不会误关同一共享连接。

逻辑流的 `SetDeadline`、`SetReadDeadline`、`SetWriteDeadline` 交给其 smux 流处理。一个流的超时不再设置到所有流共用的物理连接。MTCP/MTLS 只在创建会话时设置物理握手超时，不在复用会话上重设。

### 缺失服务恢复及策略同步

- 分别判断 TCP/UDP 是否存在，只创建缺失侧，保留仍运行侧。库存不完整不作为完整空库存使用。
- 恢复前复核规则、用户、授权、到期和流量限制；链及同节点出口成功确认后再恢复依赖入口。
- 有限速要求时，只有库存确认限速器存在或创建收到成功确认后才恢复入口；未确认时入口链和历史别名清理也暂缓，保护仍在工作的旧服务。
- 策略同步按实际存在的协议发送，历史授权别名仍继承同一用户限制。只有精确对应请求名字的不存在错误才剔除该项；离线、超时、不支持命令等保留待同步状态。管理员豁免保持不变。
- 历史别名清理独立删除 TCP/UDP，兼容旧 Agent 配对删除预检导致单侧残留的情况。校验规则及授权归属，保护当前授权和其他用户规则。
- 新 Agent 删除命令对缺失成员幂等，也清除没有监听的对应持久配置；完整校验名字后才操作，不扩大到其他规则。
- 孤儿清理同时识别 TCP/UDP，按完整规则和授权名字去重；只剩 UDP 时仍可清理，不把不完整库存或数据库查询结果解释为规则已不存在。
- 可选 REST 接口与面板 WebSocket 共用服务变更锁。REST 更新在关闭监听前继承旧用户策略并检查整批版本；旧格式请求省略策略不会移除限制，非法 JSON 和非法热策略直接拒绝。没有自动开启 REST。其原有监听绑定失败后的完整事务回滚不在此修改范围。

## 可选复用诊断

节点详情显示复用物理会话数、逻辑流数、累计创建和关闭数。它们统计 GOST smux 会话，不表示在线用户数；两端数字不能相加当作唯一连接数。普通 TCP、QUIC 和其他进程不在此指标中，累计计数在 Agent 重启后清零。

诊断默认关闭，未开启或旧 Agent 未上报时显示 `--`，不把没有采集解释为零。确需诊断时，可在未来经批准的维护窗口中给 Agent 进程设置 `LUNARIS_MUX_METRICS=1`；环境只在启动时读取。此次源码工作没有修改任何机器的进程环境或重启服务。

关闭时 smux 直接使用原始连接，没有诊断包装、注册表跟踪或逐包开关检查。开启时只在创建/关闭阶段跟踪会话，详细指标使用已有缓存采样，不增加每会话监控 goroutine。关闭 smux 或 keepalive 到期均释放跟踪引用；保留底层可选 scatter/gather 写接口。

Windows `net.Pipe` 最近一次各五次一秒样本中，开启诊断均值约 1259 MB/s，关闭约 1303 MB/s，差距约 3.4%；两者每次操作均为 31 次分配。采样顺序未交错，结果包含时间漂移和调度噪声，不能把差距完全归因于诊断。早期独立样本差距约 1.3%。因此默认关闭诊断，不能声称生产吞吐提升或开启诊断没有代价。确定性的超时隔离和连接复用修复默认生效。

```sh
cd go-gost
go test -mod=readonly ./...
cd x
go test -mod=readonly ./...
go test -race -count=3 ./internal/net/udp ./internal/util/mux ./dialer ./service ./socket ./api
go test -run '^$' -bench BenchmarkMuxTransfer -benchmem ./internal/util/mux
```

Java 单元测试使用 Java 21 / Maven。前端行为回归使用 `node --test tests/forward-bulk.test.mjs`，生产构建使用 `npm run build`。安装器入口、LF 校验和及发布决策契约由现有 Python 测试验证。Linux 构建、MySQL 5.7/8.4 容器集成和 UDP 原版对照基准交给 PR 验证工作流。

此次升级在独立源码工作树完成，未连接、部署或重启生产服务器，未改主分支或发布版本。保留永久安装器入口、原目录、Compose 项目/卷和凭据契约。旧 Agent 仅持久化、已暂停的别名配置需要新 Agent 的幂等删除支持，不能通过自动恢复旧服务来清理。真实线路吞吐和长期负载尚未验证。
